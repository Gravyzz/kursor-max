# Финальная сдача Курсора

Для очного финала организаторы попросили до **26 октября 2026 года, 12:00 МСК** заново приложить тот же список материалов, что и на онлайн-этапе, включая код. Комплект «Курсора» собирается одним ZIP меньше 18 МБ: презентация остаётся главным документом, рядом лежат исходный код, машиночитаемые материалы API и закрытый временный доступ к стенду.

## Что должно быть готово перед сборкой

1. Публичный репозиторий с чистой историей финальной версии и зелёным CI.
2. Тот же коммит развёрнут на сервере.
3. Бот открывает мини-приложение в мобильном и веб-клиенте MAX.
4. На сервере задан отдельный `REVIEW_API_KEY`; `/api/config` возвращает `reviewAuth: true`.
5. Презентация экспортирована в PDF и содержит ссылку на бота, публичный репозиторий и короткий сценарий проверки.
6. Зафиксирован хеш последнего коммита: `git rev-parse HEAD`.

## Содержимое закрытого архива

Скрипт `scripts/build-submission.sh` собирает:

- `Kursor-SQUAD70.pdf` — презентацию команды;
- `source-code.zip` — исходный код зафиксированного публичного коммита;
- `SHA256SUMS.txt` — контрольные суммы переданных файлов;
- `README.txt` — бот, стенд, репозиторий, точный commit hash и порядок проверки;
- `openapi.yaml` — описание основных методов API;
- `DATA-API.yaml` — последовательный проверочный сценарий;
- `test-data.json` — только модельные данные;
- `REVIEW-ACCESS.txt` — временный ключ API, который нельзя публиковать в GitHub.

## Как собрать

Создайте вне репозитория текстовый файл `REVIEW-ACCESS.txt`:

```text
X-Review-Key: <значение REVIEW_API_KEY с сервера>
```

Затем из корня проекта выполните:

```bash
./scripts/build-submission.sh \
  /путь/к/презентации.pdf \
  https://github.com/Gravyzz/kursor-max \
  <полный-commit-hash> \
  /путь/к/REVIEW-ACCESS.txt
```

Готовый файл появится в `release/Хакатон MAX - Образовательные решения - SQUAD 70.zip`. Папка `release/` исключена из Git. Скрипт проверяет, что передан текущий зафиксированный commit hash, добавляет снимок исходного кода и завершится ошибкой, если архив больше 18 000 000 байт.

## Перед загрузкой финального решения

- открыть ZIP и убедиться, что PDF читается, а ссылки и хеш в `README.txt` верны;
- открыть бота по ссылке из PDF на телефоне и в веб-версии MAX;
- пройти студентом поиск и чек-лист, редактором создать страницу, деканатом опубликовать её;
- вызвать `/api/health`, затем пройти `DATA-API.yaml` с ключом из закрытого файла;
- проверить, что сервер и бот останутся включены на весь период оценки;
- загрузить ZIP через форму финального этапа и убедиться, что кабинет или форма показывает принятый файл.

После завершения оценки удалите `REVIEW_API_KEY` из серверного `.env` и перезапустите контейнеры. Бот и вход через MAX продолжат работать.
