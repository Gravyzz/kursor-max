# Дизайн мини-приложения: правила и карта экранов

Рабочее приложение `apps/miniapp` использует единую систему токенов, навигацию по ролям и настоящее API. Браузерное демо использует тот же React-код. Локальные имитации функций прототипа не являются готовыми функциями приложения.

## Навигация и права

- Док читателя: **Главная · Разделы · Поиск · Профиль**. У команды перед профилем добавляется **Редакция**; «Команда» открывается из карточки справочника в «Редакции». Доступ берётся из `editorRole` ответа API текущего справочника, а не из выбранного внешнего вида или роли в вузе.
- Док имеет доступное имя «Навигация справочника». Кнопки имеют видимые подписи 10–11 px и `aria-label`, текущая — `aria-current="page"`.
- `nav.tab` переключает корневые вкладки без кнопки «Назад» и без накопления истории. Каждая вкладка имеет один h1. `nav.push` открывает вложенную страницу; `pop` восстанавливает позицию прокрутки. Системная «Назад» MAX сначала закрывает лист.
- В конструкторе док скрыт: внизу остаётся панель сохранения и публикации. Вернуться можно экранной или системной кнопкой «Назад».
- Редактор видит страницы и вопросы; администратор также объявления и управление составом команды. Сервер продолжает проверять права каждого запроса.
- Фото профиля, логотип справочника, изменение имени, передача задач и скрытие запросов из прототипа не перенесены: для них нет серверного API.

## Правила оформления

1. **Токены и «стекло».** Цвета компонентов задаются через `--pd-*`; внешний слой — `glass.css`. Системная тема включена по умолчанию. Фон — синий градиент (ночью тёмно-фиолетовый), всё, что лежит прямо на фоне, — белое. Карточки, поиск, кнопки и док — матовое стекло с тёмными чернилами (ночью — тёмное стекло со светлыми). Основные действия и активная вкладка — градиент синий → фиолетовый; выбранный вариант в переключателях — сплошной тёмно-синий. Значки разделов — одним синим. Новую поверхность добавляйте в список «стеклянных» селекторов `glass.css`, иначе она унаследует белый текст фона. Размеры текста: 12/14/16/20/28 px, радиусы: 12/20/999 px. При создании новой поверхности проверьте наследование обоих наборов токенов.
2. **Компоненты MAX UI** используются для основных кнопок и переключателей. Тематические переменные переопределяются централизованно. Значки — Lucide, без загрузки с внешних серверов.
3. **Шрифт** — Onest (SIL OFL 1.1) из пакета `@fontsource/onest`: кириллица и латиница, 400/500/600/700, едет в сборке. Шрифты с закрытой лицензией не подключаем — это требование хакатона к свободному распространению.
   Изображения кампуса для дневной и ночной темы созданы командой проекта с помощью генеративного ИИ специально для «Курсора».
4. **Широкий экран (MAX на компьютере, от 900 px).** Та же структура, что на телефоне: колонка 860 px по центру, фото кампуса на главной — карточка по ширине колонки (исходник 780 px на всё окно не растягиваем: мылится), плитки главной в четыре колонки, разделы — в две, нижний док остаётся. Правила — в конце `glass.css`.
5. **Ширина от 320 px.** Проверять на 320, 375 и 430 px. Сетки полей — `minmax(0, 1fr)`, растягиваемые элементы — `min-width: 0`. Контролы и текст не должны выходить за поверхность или создавать горизонтальную прокрутку.
6. **Зона нажатия** не меньше 40 × 40 px, в том числе у кнопок дока, стрелок блока и удаления пункта. Подпись значка должна оставаться доступной скринридеру.
7. **Нижние панели** учитывают `env(safe-area-inset-bottom)`. Контент заканчивается выше дока или панели сохранения. Тост не перекрывает активные нижние кнопки.
8. **Контраст** проверяется на обоих концах градиента (`--pd-day` / `--pd-day-end`, ночью `--pd-night` / `--pd-night-end`) и на стекле в обеих темах: текст не ниже 4.5:1, крупный текст и значки — 3:1. Верх дневного градиента не светлее `#3e6aa8`: иначе мелкий белый текст опускается до 3:1. На фото главной белый текст держится за счёт затемнения снизу. Цвета — только токены, локальные цвета в компонентах не добавляются.
9. **Фокус и движение.** Видимый фокус обязателен. Раскрывающиеся элементы используют `aria-expanded`, вкладки — роли и `aria-selected`. Учитывать `prefers-reduced-motion`.
10. **QR-плакат белый** в обеих темах: его печатают и сканируют. Тексты интерфейса по-русски, ошибки подсказывают дальнейшее действие.

## Поведение экранов

- Главная: фото кампуса во весь верх экрана (день/ночь) с приветствием и названием поверх, поиск, срочное, объявления, чеклисты, разделы и помощь. Знака справочника и ленты популярных запросов на главной нет — запросы на экране «Поиск». Нулевой прогресс не рисуется; новый чеклист предлагается в «С чего начать».
- Значки разделов выбираются в редакторе и хранятся в существующем поле `emoji`. Код не угадывает их по названию; все значки одного синего цвета.
- Редакция: компактные строки, сворачиваемые разделы, исключительные статусы и приоритет проблем: «Требует внимания» — по доле «не помогла» (от 25 % при 5+ оценках или 10+ жалоб при доле от 20 %), сортировка по числу жалоб; также проверка и устаревание.
- Профиль: одна карточка настроек без заголовков групп — программа, курс шкалой 1–6 (сохраняется, когда ползунок отпущен), общежитие «Да / Нет», напоминания. Программа сохраняется после паузы, потери фокуса или ухода; остальное — при выборе. Переключатели — отдельные капсулы. Роль показана меткой, рабочих дублей навигации и кнопки «Готово» нет.
- Команда: пояснение ролей — подсказка «Кто что делает» по нажатию, а не абзац над списком.

## Проверка

```bash
cd apps/server && npm run typecheck && npm test
cd apps/miniapp && npm run build
cd apps/demo && npm run smoke && npm run build && npm run e2e
```

Для серверных интеграционных тестов задайте `TEST_DATABASE_URL` с отдельной PostgreSQL. Для e2e сначала установите Chromium: `npx playwright install chromium` в `apps/demo`.

Сквозной тест `apps/demo/test/e2e.mjs` проходит реальный интерфейс собранного демо: поиск в боте и приложении, разделы и сроки, отметки чек-листа, темы, объявления и архив, вопрос → ответ → сообщение, публикацию, QR, сворачивание блоков и сохранение при медленном ответе. Он также проверяет права студента/редактора/администратора, контраст обеих тем (≥4.5:1), отсутствие дублей объявлений и нулевого прогресса, автосохранение профиля, сохранение значков разделов, приоритет проблемных страниц и выход за границы на 320/375/430 px. Снимки шагов сохраняются в `apps/demo/test/e2e-output/`.

Изменение доступных названий элементов требует обновления теста в том же коммите. Браузерное демо не заменяет ручную проверку в мобильном и веб-клиенте MAX: подпись входа, диплинки, системная «Назад», QR, отправка и открытие ссылок.
