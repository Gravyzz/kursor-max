# Данные и приватность в Курсоре

Версия для хакатонного стенда. Для коммерческого запуска университет назначает оператора персональных данных и дополняет документ своими реквизитами, сроками хранения и каналом обращений.

## Какие данные используются

- идентификатор, имя, фамилия, username и временная ссылка на фотографию, которые MAX передаёт в подписанных данных запуска;
- роль в университете, факультет, группа и курс, если университет заранее загрузил эти сведения или пользователь вошёл по приглашению;
- личные настройки справочника: курс, программа, проживание в общежитии, интересующие теги и уведомления;
- личный прогресс в чек-листах, оценки полезности страниц и вопросы дежурному;
- технические события для аналитики: поисковая фраза, число результатов, открытие страницы и время действия.

Документы, медицинские сведения, причины пропусков, оценки и платёжные данные приложение не запрашивает.

## Для чего они нужны

- показать подходящий факультетский справочник и персональные разделы;
- сохранить прогресс пользователя;
- доставить ответ дежурного и напоминания в личный чат MAX;
- показать редакторам агрегированные пробелы в справочнике и устаревшие страницы;
- проверить права редактора и вести журнал значимых изменений.

## Кто что видит

- студент видит собственный профиль, прогресс, вопросы и опубликованный справочник;
- редактор видит содержание своего справочника, поступившие вопросы и агрегированную аналитику;
- администратор справочника управляет командой, публикациями и объявлениями;
- оператор сервера имеет технический доступ к базе только для эксплуатации и восстановления.

Персональный прогресс отдельного студента не выводится редакторам в аналитике. Демо-данные помечены как модельные и создаются в отдельном модельном университете.

## Хранение и защита

- соединение с публичным стендом работает по HTTPS;
- вход мини-приложения проверяется по подписи `initData` MAX и ограничен по времени;
- телефоны для сопоставления хранятся в виде HMAC-хеша с серверным секретом, исходный номер не сохраняется;
- секреты находятся в `.env` на сервере и исключены из Git;
- база не публикует порт в интернет, API ограничивает частоту запросов, журнал контейнеров ротируется;
- резервные копии должен хранить оператор в зашифрованном виде с ограниченным доступом.

## Сроки и удаление

На пилоте данные хранятся до завершения пилота или до запроса пользователя/университета. Модельную песочницу можно полностью пересоздать командой «Сбросить демо». До появления самостоятельного удаления аккаунта запрос на удаление обрабатывает оператор стенда вручную: он удаляет связь пользователя, профиль, прогресс и вопросы из базы. Для промышленного запуска канал обращения и точный срок исполнения фиксируются в договоре с университетом.

## Внешние системы

Курсор обращается к MAX Bot API для сообщений, кнопок и уведомлений. На сервере используется PostgreSQL. Рекламные сети, платёжные системы и сторонняя продуктовая аналитика в текущем решении отсутствуют.
