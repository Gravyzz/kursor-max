# Проверка API Курсора

Спецификация основных методов находится в [`openapi.yaml`](../openapi.yaml), последовательный машинно-читаемый сценарий — в [`DATA-API.yaml`](../DATA-API.yaml), модельные значения — в [`test-data.json`](../test-data.json).

## Безопасный доступ жюри

Продакшн принимает подписанные данные запуска MAX в заголовке `X-Max-Init-Data`. Для автоматической проверки без аккаунта MAX администратор стенда может задать `REVIEW_API_KEY`. Такой ключ:

- выключен, пока переменная пуста;
- создаёт одну отдельную модельную учётную запись;
- позволяет работать только с демо-песочницей, созданной через `POST /api/demo`;
- не заменяет аккаунт реального сотрудника и не открывает данные другого вуза;
- не хранится в GitHub и после проверки может быть удалён из `.env`.

Для сдачи значение передаётся только в закрытом файле `REVIEW-ACCESS.txt` внутри архива решения. Репозиторий содержит лишь название заголовка и сценарий.

## Ручная проверка

Подставьте адрес стенда и закрытый ключ:

```bash
BASE_URL=https://kursor.139-100-236-88.sslip.io
REVIEW_KEY='значение-из-REVIEW-ACCESS.txt'
```

Проверка доступности не требует ключа:

```bash
curl -fsS "$BASE_URL/api/health"
```

Создайте чистую демо-песочницу в роли деканата:

```bash
curl -fsS -X POST "$BASE_URL/api/demo" \
  -H "X-Review-Key: $REVIEW_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"role":"dean"}'
```

Скопируйте `handbookId` из ответа. После этого доступны читательские и редакторские методы:

```bash
curl -fsS --get "$BASE_URL/api/handbook/search" \
  --data-urlencode 'handbookId=ID_СПРАВОЧНИКА' \
  --data-urlencode 'q=справка' \
  -H "X-Review-Key: $REVIEW_KEY"

curl -fsS "$BASE_URL/api/handbook-editor/analytics?handbookId=ID_СПРАВОЧНИКА" \
  -H "X-Review-Key: $REVIEW_KEY"
```

Повторный `POST /api/demo` удаляет только прежнюю песочницу этой модельной учётной записи и создаёт чистую. Реальные данные не затрагиваются.
