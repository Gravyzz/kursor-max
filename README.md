# Курсор — конструктор справочников для факультетов в MAX

Университет подключает факультеты к Курсору, каждый факультет собирает свой справочник из готового шаблона и ведёт его с телефона, а студенты пользуются им в чат-боте и мини-приложении MAX. Клиент и плательщик — университет; пилот может начинаться с одного факультета.
Трек «Образовательные решения», Хакатон MAX 2026.

Живой справочник вместо PDF и десятка чатов: учёба, справки, физкультура, общежитие, деньги, куда идти с проблемой. Любой факультет собирает свой справочник из готовой структуры и ведёт его с телефона. Студент спрашивает прямо в чате с ботом («физра отработки», «хвосты», «бумажка об обучении») и получает выдержку со ссылкой на страницу.

**Бот в MAX:** https://max.ru/t753_hakaton_max_bot?start=demo · **Стенд:** https://kursor.139-100-236-88.sslip.io · **Код:** https://github.com/Gravyzz/kursor-max

Проверяемый коммит указывается в файле сдачи после финальной фиксации версии. Сам README не содержит собственный хеш, потому что изменение README создаёт уже следующий коммит.

| Как проверить | Что сделать |
|---|---|
| **В MAX** | Откройте ссылку на бота выше — бот спросит, кем посмотреть (студент, редактор или деканат), и создаст личную демо-песочницу с наполненным справочником. |
| **Локально, без токена** | `docker compose up --build -d`, затем http://localhost:9090/__mock/ → «Старт: демо». Напишите боту «как получить справку». |
| **В браузере, без Docker** | Нужен Node.js 22. Из корня репозитория: `npm ci --prefix apps/server && npm ci --prefix apps/miniapp && npm ci --prefix apps/demo && npm run build --prefix apps/demo`, затем откройте файл `apps/demo/dist/demo.html` в Chrome или Firefox. Бот, API и PostgreSQL (PGlite) работают прямо в странице на том же коде; демо собирается из кода сервера и мини-приложения, поэтому нужны зависимости всех трёх папок. |

Для проверки создания с нуля выберите в демо роль **«Редактор»**, откройте **«Разделы» → «Новый справочник»**, задайте название, затем в редакторе нажмите **«Новый раздел»** и добавьте страницу. В своей демо-песочнице создатель нового справочника получает права администратора. Настоящие справочники вуза создаёт деканат.

Технические материалы: [`openapi.yaml`](openapi.yaml), [`DATA-API.yaml`](DATA-API.yaml), [проверка API](docs/API_REVIEW.md), [данные и приватность](docs/DATA_POLICY.md), [развёртывание](docs/DEPLOY.md), [финальная сдача](docs/SUBMISSION.md).

## 1. Назначение решения

Студент тратит недели на выяснение того, что в вузе давно известно: где взять справку, как закрыть физкультуру, до какого числа подать на общежитие, что будет, если не сдал. Ответы существуют — но разбросаны по PDF, сайту, чатам и памяти старшекурсников. Студсоветы во многих вузах собирают их вручную: на ИТ-факультете ТГУ такой справочник называют «хитсовником». Каждый факультет делает его заново, он быстро устаревает, и никто не знает, чего в нём не хватает.

Конструктор справочника, который живёт в MAX и не устаревает:

- **Студент** открывает справочник без регистрации — достаточно аккаунта MAX. Видит только то, что касается его: первокурснику — чек-лист первой недели, живущему в общежитии — раздел про заселение и оплату. Спрашивает прямо в чате и получает выдержку со ссылкой на страницу. Отмечает сделанное в чеклистах, получает напоминания о сроках.
- **Редактор** — студсовет, тьютор, учебный офис — ведёт справочник с телефона: страница собирается из 12 типов блоков (текст, шаги, чеклист, вопросы-ответы, контакт, место, срок, ссылка, файл, важное, чат, словарь), есть предпросмотр «как увидит студент», черновик → проверка → публикация, история публикаций.
- **Редактор видит бэклог**, который пишут сами студенты: что искали и не нашли, какие страницы отмечают бесполезными, какие пора перепроверить, какие вопросы остались без ответа. Ответ дежурного приходит студенту в чат и одним нажатием превращается в пункт «Вопросы и ответы» на странице.
- **Деканат** создаёт справочник факультета одной кнопкой: приходит готовая структура из восьми разделов и ~25 страниц-заготовок с подсказками, что вписать. Общеуниверситетские страницы наследуются — факультет переписывает только то, что у него устроено иначе. Команду — студсовет и учебный офис — деканат приглашает личными ссылками прямо из мини-приложения, объявления рассылает адресно по курсам.

Короткие действия, поиск и уведомления живут в чате с ботом. Разделы, длинные инструкции, чеклисты и редактор — в мини-приложении. Подробная продуктовая концепция — в [`docs/HANDBOOK.md`](docs/HANDBOOK.md), коммерческая модель и порядок выдачи доступов — в [`docs/COMMERCIAL_MODEL.md`](docs/COMMERCIAL_MODEL.md), проблема, As Is → To Be, гипотеза эффекта, пилот и масштабирование — в [`docs/PILOT_AND_SCALING.md`](docs/PILOT_AND_SCALING.md).

## 2. Основной пользовательский сценарий

**Студент — вопрос в чате и ответ**

| # | Шаг | Где | Что происходит |
|---|---|---|---|
| 1 | Вход | Чат | Ссылка факультета — ссылка на бота с параметром `?start=hb_<слаг>` — из чата курса или от куратора. Запись в списках деканата не нужна. |
| 2 | Вопрос | Чат | Студент пишет «физра отработки». Бот приводит сленг к словам справочника, находит страницу и отвечает выдержкой с кнопкой «Открыть страницу». Если точного совпадения нет — так и говорит и предлагает спросить дежурного. |
| 3 | Страница | Мини-приложение | Шаги, сроки, контакты, чеклист с личным прогрессом, «Частые вопросы». Внизу — «Страница помогла?»: ответ попадает редактору. |
| 4 | Профиль | Мини-приложение | Курс и общежитие — и справочник скрывает лишнее: не живущему в общежитии его раздел не мешает. |
| 5 | Сроки | Чат | «Заявление на общежитие — через 3 дня», «Отработки закрываются через неделю» — заранее, только тем, кого это касается. |
| 6 | Чего нет | Чат | «Спросить дежурного» → вопрос уходит редакторам, ответ приходит в чат. Запрос без ответа попадает в бэклог редактора. |

**Деканат — справочник с нуля**

| # | Шаг | Где | Что происходит |
|---|---|---|---|
| 1 | Вход | Чат | Личная ссылка `?start=inv_<код>` из команды `bootstrap` связывает аккаунт MAX с записью сотрудника деканата. |
| 2 | Создание | Мини-приложение | «Создать справочник» → 8 разделов и ~25 заготовок; страницы вуза наследуются. |
| 3 | Команда | Мини-приложение | «Редакция» → «Команда» → «Пригласить в команду»: ФИО, студсовет или сотрудник, права редактора или администратора → личная ссылка, которую можно сразу переслать в MAX. |
| 4 | Наполнение | Мини-приложение | Редакторы собирают страницы из блоков и отправляют на проверку; администратор получает уведомление в чат и публикует. |
| 5 | Ссылка студентам | Чат курса | Ссылка на бота с параметром `?start=hb_<слаг>` — справочник открывается у любого студента. |
| 6 | Жизнь | Мини-приложение | «Что ищут студенты» → метрики пилота (нашли ответ сами, страница помогла, время ответа дежурного, свежесть), пробелы, вопросы без ответа, слабые и устаревшие страницы. «Объявление» → адресная рассылка по курсам. |

## 3. Состав и архитектура

```
        Пользователь MAX (iOS, Android, веб)
          │ чат с ботом               │ мини-приложение (WebView + MAX Bridge)
          ▼                           ▼
┌─────────────────────┐    ┌──────────────────────────────────────────┐
│ MAX Bot API         │    │ web: Caddy 2                             │
│ platform-api2.max.ru│    │ HTTPS, статика мини-приложения,          │
│ (локально max-mock) │    │ /api → api:3000, /webhook → bot:3001     │
└───┬─────────────▲───┘    └────────────────────┬─────────────────────┘
    │ обновления  │ сообщения                   │ REST + подпись initData
    ▼             │                             ▼
┌─────────┐  ┌────┴─────┐                  ┌─────────┐
│ bot     │  │ worker   │                  │ api     │
└────┬────┘  └────┬─────┘                  └────┬────┘
     └────────────┴──────────────┬──────────────┘
                                 ▼  общий код домена
                       ┌──────────────────┐
                       │ db: PostgreSQL   │  данные, очередь уведомлений, аудит
                       └──────────────────┘
```

| Сервис в compose | Технологии | Назначение |
|---|---|---|
| `web` | Caddy 2; React 19, Vite 7, MAX UI, MAX Bridge | Отдаёт мини-приложение, проксирует `/api` и `/webhook`. На сервере сам получает TLS-сертификат |
| `api` | Node.js 22, TypeScript, Fastify 5, Zod | REST для мини-приложения: проверка подписи `initData`, права, операции справочника |
| `bot` | `@maxhub/max-bot-api` 0.3.1 | Обновления MAX (long polling или webhook): поиск по справочнику в чате, вход по приглашению, демо |
| `worker` | Node.js 22 | Очередь уведомлений: отправка с повторами и лимитом частоты, напоминания о сроках из блоков «Срок» |
| `migrate` | тот же образ, что `api` | Применяет SQL-миграции и завершается |
| `db` | PostgreSQL 16 | Данные, очередь уведомлений, журнал поиска, журнал аудита |
| `max-mock` | Node.js, без зависимостей | **Только для локальной проверки:** имитация MAX Bot API и страница-чат вместо клиента MAX |

`api`, `bot`, `worker` и `migrate` собираются из одного образа `apps/server`, роль задаётся командой запуска.

**Ключевые технические решения**

- **Страница справочника — это данные, а не вёрстка.** Страница собирается из блоков (`apps/server/src/domain/handbook.ts`, 12 типов, jsonb + проверка схемой Zod). Поэтому её можно редактировать с телефона, искать полнотекстовым поиском, а блоки «Срок» и «Чеклист» автоматически становятся напоминаниями и личным прогрессом.
- **Наследование справочников.** Справочник факультета наследует справочник вуза: одинаковое пишется один раз, факультет переопределяет только то, что у него устроено иначе (`inherited_from`). Студент видит одну страницу, а не две.
- **Адресность.** У страницы, раздела, блока, срока и объявления есть аудитория (курс, общежитие, теги). Совпадение считает SQL-функция `audience_matches` — одинаково в списках, поиске, напоминаниях и рассылке. Незаполненный профиль ничего не скрывает.
- **Поиск на языке студента.** Полнотекстовый поиск PostgreSQL по русскому словарю. Разговорные формы приводятся к словам справочника («физра» → физкультура, «хвосты» → академическая задолженность). Заголовок страницы и название раздела весят больше текста (`setweight` A и B). Перекрытые наследованием страницы из выдачи убираются. Нет точного совпадения — поиск по любому слову, затем опечаточный через `pg_trgm`, и ответ честно помечается как неточный.
- **Уведомления через outbox.** Операция и уведомление записываются в одной транзакции. `worker` забирает пачки через `FOR UPDATE SKIP LOCKED`, не дублирует по ключу, повторяет с растущей паузой и отправляет не больше `NOTIFY_RPS` сообщений в секунду (лимит MAX Bot API — 30 запросов в секунду). Напоминания о сроках ставит тот же `worker` раз в тик по полю `remind_days` блока «Срок».
- **Идемпотентный приём обновлений.** Ключ каждого события MAX сохраняется в `processed_updates`: повторная доставка webhook или перезапуск бота не выполнят действие дважды.

**REST API мини-приложения.** Основной вход использует заголовок `X-Max-Init-Data` с подписанными данными запуска. На локальном стенде вместо него допускается `X-Dev-User` (только при `DEV_AUTH=true`). Для автоматической проверки жюри можно временно включить `X-Review-Key`: он ведёт только в отдельную модельную песочницу. Основные методы описаны в [`openapi.yaml`](openapi.yaml), последовательность проверки — в [`DATA-API.yaml`](DATA-API.yaml).

## 4. Запуск одной командой

Из корня репозитория:

```bash
docker compose up --build -d
```

Команда собирает образы и поднимает все локальные компоненты: `db`, `migrate`, `api`, `bot`, `worker`, `web` и имитацию MAX `max-mock`. Файл `.env` не нужен: в `compose.yaml` заложены безопасные значения по умолчанию для офлайн-стенда. Чтобы поменять настройки, скопируйте пример: `cp .env.example .env`.

**Если Docker Hub недоступен из вашей сети** (ошибки `403`, `429` или тайм-аут на `docker.io/library/...`), возьмите базовые образы из зеркала:

```bash
IMAGE_REGISTRY=dockerhub.timeweb.cloud/library docker compose up --build -d
```

**Готовность:** `docker compose ps` — у `api` статус `healthy`, остальные `Up`. Одноразовый `migrate` завершается со статусом `Exited (0)` (виден в `docker compose ps -a`).

| Адрес | Что там |
|---|---|
| http://localhost:9090/__mock/ | Чат с ботом: имитация клиента MAX. Кнопки мини-приложения открывают его в новой вкладке |
| http://localhost:8080/?dev_user=100500 | Мини-приложение напрямую, с тестовым входом за пользователя `100500` |
| http://localhost:8080/api/health | Проверка API: `{"ok":true,...}` |

## 5. Необходимые параметры окружения

**Локальный стенд:** Docker Engine 24+ и Docker Compose v2.24+, свободные порты `8080` и `9090` на `127.0.0.1`, 2 ГБ RAM и 3 ГБ на диске. Интернет нужен только при первой сборке (базовые образы и `registry.npmjs.org`).

**Сервер для проверки в MAX:** VPS с Linux, 1–2 vCPU и 2 ГБ RAM, публичный IP, открытые порты `80` и `443`; домен с A-записью на сервер (MAX открывает мини-приложения только по HTTPS); токен бота; ссылка мини-приложения `https://<домен>/` в настройках бота на платформе для партнёров MAX.

| `APP_TIMEZONE` | `Europe/Moscow` | часовой пояс вуза | Часовой пояс по умолчанию для сроков; только имя вида `Europe/Moscow` или `Asia/Tomsk`, сокращения вроде `MSK` не принимаются |

| `WORKER_TICK_MS` | `3000` | `3000` | Как часто `worker` проверяет очередь уведомлений, мс |
| `RATE_LIMIT_PER_MINUTE` | `600` | `600` | Запросов к API в минуту с одного IP |
| `INITDATA_MAX_AGE_SEC` | `86400` | `86400` | Сколько секунд действительны данные запуска мини-приложения из MAX |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | то же | Кому API верит в `X-Forwarded-For`: соседнему прокси (Caddy из compose); менять, только если API стоит за другим прокси |
| `WEB_BIND`, `MOCK_BIND`, `MOCK_MINIAPP_URL` | `127.0.0.1:8080`, `127.0.0.1:9090`, `http://localhost:8080/` | — | Публикация портов локального стенда |

Каждая настройка сервера из `.env` доходит до контейнеров `migrate`, `api`, `bot` и `worker` — CI сверяет список с `apps/server/src/config.ts`. Не настраиваются: `API_PORT=3000`, `BOT_PORT=3001` и `WEBHOOK_PATH=/webhook/max` (на них опирается `apps/miniapp/Caddyfile`), `DATABASE_URL` compose собирает из `POSTGRES_*`.

`spravochnik` в именах базы и её пользователя, compose-проекта, Docker-образов и пакетов `@spravochnik/*` — внутреннее имя проекта до названия «Курсор». Его не меняем: от имени compose-проекта зависит имя тома с базой (`spravochnik_pgdata`), и переименование оставило бы уже поднятый стенд без данных.

## 10. Работа с данными

| Данные | Откуда | Кто видит |
|---|---|---|
| Вуз, институты | Команда `bootstrap`, демо | Участники этого вуза |
| Записи вуза: деканат, редакторы (ФИО, роль) | `bootstrap`, приглашения из мини-приложения | Администраторы справочника |
| Аккаунт MAX: id, имя и фамилия из профиля | Проверенные `initData` или обновление бота | Только для связи с записью вуза |
| Читатель справочника: курс, общежитие, теги, согласие на напоминания, прогресс чеклистов | Сам студент в мини-приложении | Только сам читатель; редакторы — в обезличенных агрегатах |
| Содержимое справочника, версии страниц | Редакторы | Опубликованное — все читатели, черновики — команда |
| Журнал поиска, оценки страниц, вопросы дежурному | Действия читателей | Команда справочника (аналитика) |
| Уведомления и журнал аудита | Сервер | Администратор БД |

Среди первокурсников бывают несовершеннолетние (17 лет), поэтому справочник не спрашивает возраст, документы, сведения о здоровье и причинах пропусков; вопросы дежурному студент пишет сам и видит, что их читает команда справочника. Оператор персональных данных — вуз, обработка — по 152-ФЗ «О персональных данных»; в демо все данные вымышлены.

Принципы: минимум персональных данных (никаких документов, справок и причин пропусков); личное — только в личном диалоге с ботом; идентификатор пользователя берётся только из проверенной подписи `initData` или из обновления MAX; демо-песочница создаётся отдельным «вузом» для каждого аккаунта MAX. Резервная копия: `docker compose exec db pg_dump -U spravochnik spravochnik > backup.sql`.

## 11. Тестовые данные

Все данные в демо **вымышлены** и помечены баннером «Демо: «Модельный университет», данные вымышлены».

**Демо-песочница** создаётся командой `/demo`, ссылкой `?start=demo`, кнопкой «Попробовать демо» в чате или карточками ролей на первом экране мини-приложения. Сначала выбирается роль:

| Роль | Что доступно |
|---|---|
| 🎓 Студент | Читать справочник, искать в чате, отмечать чек-листы, задавать вопросы дежурному, убирать объявления в архив. Редактор закрыт. |
| ✏️ Редактор (студсовет) | Всё, что у студента, плюс черновики страниц, отправка на проверку и ответы на вопросы. |
| 📚 Деканат | Всё: публикация, объявления, команда, аналитика, справочники других факультетов. |

Роль меняется в любой момент — «Сменить роль» в чате или «Роль» в баннере мини-приложения; сделанное сохраняется. В настоящем вузе роль выдаёт деканат личной ссылкой-приглашением, выбрать её самому нельзя. Для каждого аккаунта MAX — отдельная копия:

- «Модельный университет», институт информационных технологий; вы — в выбранной роли и одновременно читатель 1 курса;
- **наполненный справочник ИИТ**: 19 опубликованных страниц с настоящим содержанием (чек-лист первой недели, БРС и сессия, справки, физкультура, общежитие, стипендии, «куда обратиться»), справочник вуза над ним с наследованием и переопределённой страницей, одна страница на проверке, объявление, сроки, журнал поиска, три вопроса дежурному без ответа и четыре отвеченных — чтобы аналитика и метрики пилота были не пустыми;
- команда из двух редакторов-студентов и 40 модельных читателей; модельным пользователям настоящие сообщения не отправляются.

Сбросить демо: «Сбросить» в баннере мини-приложения, «Сбросить демо» в чате или `/reset`. Сроки считаются от текущей даты, поэтому демо актуально в любой день.

## 12. Пошаговый сценарий проверки

### А. В MAX (мобильное приложение или веб-версия)

1. Откройте `https://max.ru/t753_hakaton_max_bot?start=demo` (ссылка — в начале README). Бот спросит, кем посмотреть демо: «Студент», «Редактор» или «Деканат». Для полного сценария выберите **«Деканат»** — придёт «🎓 Демо «Модельного университета»…» с кнопками «Открыть справочник», «Редактор справочника», «Сменить роль», «Сбросить демо».
2. **Вопрос в чате.** Напишите `как получить справку` — придёт выдержка со страницы «Справка об обучении» и кнопка «Открыть страницу». Попробуйте `физра отработки` и `хвосты`. Напишите `есть ли военная кафедра` — бот честно скажет «Точного ответа не нашлось» или «В справочнике такого пока нет» и предложит спросить дежурного.
3. **Справочник.** «Открыть справочник»: объявление, ближайшие сроки, незаконченные чеклисты, разделы. Нажмите объявление — откроется связанная страница; «Прочитано ✓» уберёт его в архив («Архив объявлений» под списком, оттуда можно вернуть). «Первокурснику» → «Чек-лист первой недели» → отметьте пункты — прогресс виден на главной.
4. **Адресность и оформление.** В нижнем доке «Профиль» → передвиньте шкалу «Курс» на 3, «Живу в общежитии» → «Нет» — выбор сохранится автоматически. Раздел «Общежитие» исчезнет, появится «Практика». Тема по умолчанию — как в системе телефона; «Профиль» → «Оформление» переключает на светлую или тёмную.
5. **Редакция.** «Редакция» в нижнем доке → вкладка «Страницы»; статусы можно отфильтровать. «Перевод на другой профиль» ждёт проверки: откройте, «Предпросмотр», добавьте блок «Срок» — изменения сохраняются сами, незаполненное подсвечивается. «Опубликовать» — страница сразу находится поиском.
6. **QR-плакат.** Откройте опубликованную страницу в редакторе → «QR-плакат»: картинка для печати с названием страницы и кодом. Наведите камеру телефона — страница откроется в MAX. На телефоне сканер есть и в самом приложении: «Поиск» → «Сканировать QR-код».
7. **Бэклог и метрики.** «Редакция» → «Аналитика» → метрики пилота с целями (в демо «Нашли ответ сами» ниже цели — ниже видно, каких страниц не хватает), запросы без ответа, вопросы, устаревшие страницы. На вкладке «Вопросы» в «Редакции» «Ответить» — ответ уйдёт в чат.
8. **Команда.** «Редакция» → «Команда» → «Пригласить в команду» → ФИО, «Сотрудник», «Редактор» → «Создать ссылку» → «Отправить ссылку». Откройте ссылку со второго аккаунта MAX — бот ответит «Вы редактор справочника…».
9. **Объявление.** «Редакция» → вкладка «Объявления» → «Новое объявление» → заголовок, текст, «Ссылка на страницу» → любая опубликованная, «1 курс» → «Опубликовать». Уведомление с кнопкой «Подробнее» придёт в чат (в демо вы читатель первого курса). В «Редакции», на вкладке «Объявления», нажмите объявление — можно исправить текст, срок и страницу или удалить его; видно, сколько человек прочитали.
10. **Справочники факультетов.** «Редакция» → «Справочники» → список справочников и «Создать ещё один»: новый справочник придёт с 8 разделами и заготовками-черновиками.
11. **Роли.** «Сменить роль» в чате → «Студент»: остаются только чтение, поиск и вопросы, вкладка «Редакция» пропадает, а ссылка на редактор отвечает «Раздел для команды справочника». «Редактор»: черновики, проверка и ответы на вопросы, без публикации и объявлений.

### Б. Локально, без MAX и токена

1. `docker compose up --build -d` и дождитесь `api` — `healthy`.
2. Откройте http://localhost:9090/__mock/ — это чат с ботом. Нажмите **«Старт: демо»**.
3. Callback-кнопки отправляются боту, кнопки мини-приложения открывают http://localhost:8080 в новой вкладке с тестовым входом за того же пользователя.
4. Пройдите шаги 2–11 сценария А (кроме сканирования QR — в браузере нет камеры MAX; ссылку с плаката можно открыть вручную). Для шага 8 отправьте в чат-имитацию код из ссылки (`H-XXXX-XXXX`) за другого `user_id` — поле в шапке страницы-чата.
5. Уведомления (объявление, ответ дежурного, страница на проверке, напоминание о сроке) появляются в чате в течение нескольких секунд — их отправляет `worker`.

**Подключение реального вуза** (без демо):

```bash
docker compose exec api node dist/index.js bootstrap \
  --university "Модельный университет" --short "МУ" \
  --institute "Институт экономики" --timezone Europe/Moscow \
  --dean "Белова Татьяна Николаевна"
```

Команда печатает персональные ссылки на бота с параметром `?start=inv_H-XXXX-XXXX` для сотрудников деканата; повторный запуск ничего не дублирует. Дальше деканат создаёт справочник и приглашает команду из мини-приложения.

| Действие | Ожидаемый результат |
|---|---|
| Первый вход без ссылки | Бот объясняет, что умеет, и предлагает демо. Мини-приложение показывает, что умеет справочник, сканер QR-кода с плаката (на телефоне), витрину справочников, демо и поле для кода приглашения |
| `?start=demo` | Бот спрашивает роль: «Студент», «Редактор», «Деканат». Кнопки под справочником зависят от роли; «Сменить роль» меняет её без потери сделанного |

| Администратор исправил объявление | Читатели видят новый текст на главной; повторно в чат не рассылается. Удалённое объявление исчезает у всех, неотправленные уведомления отменяются |
| Отсканирован QR-код страницы другого факультета | Открывается справочник этого факультета сразу на странице с плаката, а не «страница не найдена» |
| Вопрос в чате: «физра отработки» | Выдержка со страницы «Как получить зачёт» и кнопка «Открыть страницу» |
| Вопрос, на который в справочнике нет ответа | «В справочнике такого пока нет» и «Спросить дежурного»; при частичном совпадении — «Точного ответа не нашлось. Возможно, подойдёт это:». Запрос попадает в бэклог редактора |
| «Спросить дежурного» в чате | Бот просит написать вопрос одним сообщением и называет дежурного; следующее сообщение уходит редакторам, а не в поиск. Пустых вопросов не создаётся |
| Ответ дежурного | Отвечает любой участник команды — редактор или администратор. Ответ приходит студенту в чат; при желании — сразу пункт «Вопросы и ответы» в черновике страницы |
| Студент указал «не живу в общежитии» | Раздел «Общежитие» и напоминания о заселении исчезают; незаполненный профиль ничего не скрывает |
| Страница факультета и страница вуза с одним адресом | Студент видит одну — факультетскую |
| Редактор добавил блок и не дописал его | Черновик всё равно сохраняется (автосохранение), блок подсвечен: «Срок (блок 2): Заполните название». Отправить на проверку и опубликовать такую страницу нельзя — `400` с тем же списком |
| Публикация страницы | Видна сразу, находится поиском, версия сохраняется, блоки «Срок» становятся напоминаниями |
| Страницу отправили на проверку | Студентам не видна; администраторы получают уведомление в чат с кнопкой «Открыть в редакторе» |

| Неверный или уже использованный код приглашения | Бот: «Код приглашения не найден. Проверьте код или попросите новую ссылку» |
| Больше 20 сообщений боту за минуту | Одно предупреждение «Слишком много сообщений подряд…», дальше бот молчит до конца минуты — флуд не засоряет аналитику |
| Тот же вопрос дежурному дважды | `409`: «Этот вопрос уже отправлен» |
| Срок через 3 дня, в блоке `remindDays: [3, 1]` | Читателю из аудитории срока в 10:00 по времени вуза приходит «⏰ … — через 3 дня»; ночью не будит, повторный прогон планировщика не дублирует |
| Шестой вопрос дежурному, пока пять без ответа | `409`: «У вас уже пять вопросов без ответа — дождитесь ответа дежурного» |
| Запрос к API без подписи `initData` | `401` |
| MAX временно недоступен при отправке | Уведомление остаётся в очереди и отправляется повторно (до 5 попыток) |
| MAX повторно доставил то же обновление | Событие обрабатывается один раз |

## 14. Возможности MAX сверх минимума

**Основная — справочник, который отвечает в чате.**

- *Где встроена:* шаг 2 сценария. Свободный текст в личном диалоге — это поиск по справочнику, а не заглушка «я не понимаю». Ответ приходит выдержкой с кнопкой мини-приложения на конкретную страницу.
- *Ценность:* студент спрашивает так, как спросил бы у старосты, и получает ответ за секунду. Чего нет в справочнике, уходит дежурному и возвращается ответом в тот же чат.

**Дополнительно:**

- **QR-плакат страницы (`openCodeReader`, `requestScreenMaxBrightness`).** Редактор одной кнопкой получает картинку для печати: название страницы и QR с диплинком `?startapp=hbp_<страница>`. Плакат у кабинета, в общежитии или на собрании ведёт на живую страницу, а не на её устаревшую копию. На телефоне приложение само сканирует такие коды — «Поиск» → «Сканировать QR-код» и кнопка на первом экране, а при показе плаката с экрана яркость поднимается до максимума.
- **Поделиться страницей или справочником (`shareMaxContent`).** Ссылка уходит в любой диалог MAX без копирования.
- **Диплинки с параметром запуска.** `?start=hb_<слаг>` — справочник факультета; `?start=inv_<код>` — личное приглашение в команду; `?startapp=hbp_<страница>`, `hbe_<страница>`, `hbe`, `dean` — кнопки уведомлений открывают нужный экран, а не главную.
- **Приглашение через `shareMaxContent`:** администратор отправляет личную ссылку прямо в диалог MAX.
- **Нативные элементы клиента:** системная кнопка «Назад» (`BackButton`), тактильный отклик (`HapticFeedback`), `openMaxLink` для чатов факультета, компоненты MAX UI; по умолчанию тема как в системе телефона, светлая и тёмная переключаются в профиле.

## 15. Известные ограничения

- Настоящий MAX в Docker не воспроизводится; `max-mock` реализует только используемые методы Bot API и не проверяет права и лимиты платформы. В браузере нет MAX Bridge — вход тестовый (`DEV_AUTH`).
- Поиск — полнотекстовый по словам, а не языковая модель: находит страницу, но не формулирует ответ сам. Синонимы задаются списком (общий словарь плюс словарь справочника).
- Нет загрузки файлов и картинок: блок «Файл» хранит ссылку. Новый раздел можно добавить в редакторе; переименование и удаление разделов пока доступны только через API.
- Наследование двухуровневое: вуз → факультет. Кафедральных справочников нет. Адресность — курс, общежитие и теги. Направление подготовки студент указывает в профиле, но на выдачу страниц оно пока не влияет.
- Сотрудники деканата реального вуза подключаются консольной командой `bootstrap`; веб-интерфейса администратора платформы нет.
- Имитация MAX хранит переписку в памяти: после перезапуска `max-mock` страница-чат пустая, данные в базе сохраняются.
- Демо-песочница открывается любому, у кого есть её ссылка (`hb_<слаг>` или QR страницы): так жюри может передать демо второму аккаунту. Данные в ней вымышлены; настоящие справочники вузов создаются только через `bootstrap` и деканат.
- Ограничение частоты сообщений в боте хранится в памяти процесса `bot`: при нескольких экземплярах бота лимит считается для каждого отдельно.
- Нагрузочное тестирование не проводилось.

## 16. Остановка и повторный запуск

| Задача | Команда |
|---|---|
| Остановить, сохранив данные | `docker compose stop` / `docker compose start` |
| Удалить контейнеры, сохранив тома | `docker compose down` |
| Поднять заново после изменений в коде | `docker compose up --build -d` |
| Журналы | `docker compose logs -f api bot worker` |
| Полный сброс базы | `docker compose down -v`, затем `docker compose up --build -d` |

`migrate` применяет только новые миграции, поэтому повторный `up` данные не теряет. Сервисы запущены с `restart: unless-stopped`; `api`, `bot` и `worker` корректно завершаются по `SIGTERM`.

## 17. Автотесты

Нужны Node.js 22 и, для интеграционных тестов, отдельная база PostgreSQL 16 — **тест очищает схему `public`**.

```bash
cd apps/server
npm ci
npm run typecheck
npm test                    # модульные тесты; интеграционные пропускаются без базы

docker run --rm -d --name handbook-test-db -e POSTGRES_PASSWORD=test -p 55432:5432 postgres:16-alpine
sleep 5
TEST_DATABASE_URL=postgres://postgres:test@localhost:55432/postgres npm test
docker stop handbook-test-db

cd ../miniapp
npm ci
npm run build               # проверка типов и production-сборка

cd ../demo                  # демо собирается из кода сервера и мини-приложения: npm ci в них выше обязателен
npm ci
npm run smoke               # сценарий на PGlite: тот же код сервера, бот, API, уведомления
npx playwright install chromium    # Chromium для сквозного теста; на Linux без графики: --with-deps chromium
npm run build && npm run e2e       # сценарий из раздела 12 в настоящем браузере
```

Всего 114 тестов сервера на реальной PostgreSQL; плюс сценарий демо на PGlite (`smoke`) и тот же сценарий в браузере (`e2e`).

CI (`.github/workflows/ci.yml`) запускает всё это на каждый push в любую ветку и на каждый pull request. Отдельный job проверяет Docker: `docker compose config` для локального и продакшн-профиля, сборку образов, запуск офлайн-стенда и ответ бота в имитации MAX.

## 18. Безопасность

- **Секреты** — только в `.env` (в `.gitignore`). В продакшн-режиме compose не запустится без `BOT_TOKEN`, `APP_SECRET`, `WEBHOOK_SECRET` и `POSTGRES_PASSWORD`.
- **Вход в мини-приложение** — по проверенной подписи `initData` (HMAC-SHA256, сравнение за постоянное время, срок 24 часа). `DEV_AUTH` при `NODE_ENV=production` не включается. Необязательный `REVIEW_API_KEY` сравнивается за постоянное время и открывает только отдельную демо-песочницу.
- **Webhook** принимается только с секретом подписки и только по HTTPS.
- **Права** проверяются на сервере в каждом запросе: редактирование и ответы на вопросы — по членству в справочнике, подписанному записью того же вуза; публикация, архив, аудитория страницы, объявления и команда — только администратору.
- **Входные данные** проверяются схемами Zod; тело запроса — до 3 МБ; ограничение частоты по IP в API и по пользователю в боте.
- **Контейнеры:** Node.js не от root; база и внутренние порты наружу не публикуются; размер журналов ограничен.

## 19. Развёртывание с настоящим MAX

Пошаговая инструкция с командами для Ubuntu и разбором типичных ошибок — [`docs/DEPLOY.md`](docs/DEPLOY.md). Кратко:

1. Подготовьте сервер с Docker, домен с A-записью на него, откройте порты 80 и 443.
2. `cp .env.production.example .env` и заполните `SITE_ADDRESS`, `PUBLIC_URL`, `BOT_TOKEN`, `WEBHOOK_SECRET`, `APP_SECRET`, `POSTGRES_PASSWORD`.
3. `docker compose up --build -d`.
4. Проверьте: `docker compose exec bot node dist/index.js check-max` — три строки с ✅: MAX API отвечает и называет бота, webhook указывает на `https://<домен>/webhook/max`, `/api/health` мини-приложения открывается. Если вместо первой строки ошибка TLS — команда подскажет про сертификаты Минцифры (в образе они уже подключены; запуск без Docker — в [`apps/server/certs/README.md`](apps/server/certs/README.md)).
5. В настройках бота на платформе для партнёров MAX укажите ссылку мини-приложения `https://<домен>/`.
6. Откройте в MAX ссылку на своего бота с параметром `?start=demo` и пройдите [сценарий А](#а-в-max-мобильное-приложение-или-веб-версия).
7. Для пилота подключите вуз командой `bootstrap`.

Обновление: `git pull && docker compose up --build -d` — миграции применятся автоматически.
